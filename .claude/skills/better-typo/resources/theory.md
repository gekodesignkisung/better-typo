# 편집디자인 이론 — better-typo 단일 진실 소스

이 문서는 스크립트와 LLM이 동일하게 인용하는 임계값·규칙의 단일 출처다.
판단이 필요할 때 항상 이 숫자를 근거로 삼는다.

---

## 1. 한글/CJK 줄내림 (가장 중요)

한글은 단어 사이 공백이 어절 단위라, 브라우저 기본값(`word-break: normal`)이면
어절 중간이나 조사 앞에서 줄이 끊겨 지저분해 보인다.

**기본 CSS**
```css
word-break: keep-all;       /* 어절(공백) 단위로만 줄바꿈 */
overflow-wrap: break-word;  /* 단, 한 어절이 줄보다 길면 강제 줄바꿈 허용 */
```

**의미 단위 유지 (glue)** — 끊기면 안 되는 곳에 `&nbsp;`(U+00A0) 또는 `<wbr>` 삽입:
- **조사는 앞 명사에 붙인다**: `서비스 를` 처럼 떨어지지 않게 — 단, 한글은 보통 조사가 어절에 붙어
  있으므로 주된 문제는 *어절 사이* 끊김이다.
- **숫자 + 단위**: `2026 년`, `3 개`, `50 %` → glue. **단위 집합(단일 기준)** — 스크립트(`unit-rules.mjs`)와 studio가 동일하게 따른다:
  ```
  년 개월 월 일 시 분 초  개 명 번 차 회 점 위 배 쪽 페이지
  원 달러  % px em rem pt  kg g m cm mm km ml L  주 시간
  ```
  정규식 형태: `(\d[\d,]*)[^\S\r\n]+(단위)(?![A-Za-z가-힣])` — 뒤에 글자가 붙으면(`3 개월차`의 `개`처럼 더 긴 단위의 앞부분) 오탐이므로 경계 확인. 공백에서 개행은 제외 — 줄을 넘어간 숫자|단위를 글루하면 소스의 줄 구조가 바뀐다.
- **고유명사·복합어**: `Claude Code`, `디자인 토큰`, `편집 디자인` 처럼 한 덩어리로 읽혀야 하는 구.
- **여는/닫는 괄호·따옴표**가 짝과 떨어져 줄 끝/줄 시작에 홀로 남지 않게.

**프리미티브 선택 (파일 타입별)**
- `.md` / `.html` prose: `&nbsp;` (글루) 또는 `<wbr>` (선택적 분리점)
- `.mdx` / JSX 컨텍스트: `{" "}` 또는 자기닫힘 `<wbr/>` (속성 안에는 절대 넣지 않음)

## 1-1. 적용 순서 근거 — 판형이 줄바꿈을 결정한다

줄바꿈 위치는 판형(글줄 폭·글자 크기·자간·word-break)의 함수다. 따라서 실측에 기반하는
폭 종속 교정(§1의 문맥 glue, §2 마지막 줄 한 단어)은 반드시 **텍스트(§7·§8)와 판형
CSS(§1 keep-all·§3 폭·§4 행간·§5 스케일·§6 자간)가 모두 확정된 뒤의 재실측**에 근거한다 —
판형이 바뀌면 모든 줄바꿈이 이동해 앞선 실측이 무효가 된다.
단, 숫자+단위·고정 복합어 glue는 어떤 폭에서도 끊기면 안 되는 의미 단위이므로 순서와 무관하다.

## 2. 외톨이 단어(고아, orphan) / 과부(widow)

사용자 표시 용어는 **"마지막 줄 한 단어 (방지)"** — 고아(orphan)·외톨이 같은 이론 용어 대신
현상을 그대로 말하는 표현을 쓴다. 코드 식별자(`orphan-widow`)는 그대로 둔다.

- **외톨이 단어(고아)**: 단락 마지막 줄에 짧은 단어 하나만 떨어진 상태 → 앞 공백 하나를 `&nbsp;`로 바꿔
  동반 단어를 끌어내린다.
- **과부**: 단락 첫 줄이 페이지/컬럼 맨 아래 홀로 남는 상태 (웹 단일 컬럼에선 드묾, 인지만).
- 판단 기준: 마지막 시각적 줄의 글자 수가 **4자 이하**이고 직전 줄에 여유가 있으면 고아로 본다.

## 3. 글줄 길이 (measure)

한 줄에 들어가는 글자 수. 너무 길면 다음 줄 찾기가 어렵고, 너무 짧으면 리듬이 끊긴다.

| 문자 | 권장 | 허용 |
|---|---|---|
| 한글/CJK | 25–40자 | 25–45자 |
| 라틴 | 50–65자 | 45–75자 |

제어: 본문 컨테이너에 `max-width`를 `ch` 또는 `rem`으로. 한글은 `max-width: 40ch` 부근.
(`ch`는 '0' 글자폭 기준이라 한글에선 실제보다 좁게 잡힌다 — 측정은 한글 글자폭 프로브로 보정.)

**측정 방식 (Canvas, DOM reflow 없이)**: 줄바꿈·글줄 길이 측정은 `getBoundingClientRect`나
글자별 `Range.getClientRects` 대신 **Canvas `measureText`**로 한다 — 브라우저 폰트 엔진에 바로
물어봐 레이아웃 reflow가 없다(빠르고, 반복 측정에 안전). 알고리즘은 `chenglou/pretext`(순수 JS
텍스트 측정 라이브러리)를 따른다: ① `Intl.Segmenter(word)`로 어절 분리 ② **왼쪽-접착 구두점
(`.` `,` `」` `%` 등)을 앞 단어에 병합**해 측정 — 커닝이 반영되고 줄 끝에 구두점만 홀로 떨어지는
것을 막는다(pretext RESEARCH.md의 "merge punctuation into the preceding word") ③ `keep-all`은
CJK 포함 연속 run을 하나로 병합해 재현 ④ 폭을 누적하다 초과하면 마지막 공백(break 기회)으로
되돌아가 끊는 last-break-opportunity 루프. 구현: `scripts/lib/text-measure.js`(스킬)·`probe.js`,
studio가 같은 로직을 공유한다(단일 기준). 실측 대비 줄 수 정확도 ≈95%.

## 4. 행간 (line-height)

| 대상 | 권장 비율 (line-height / font-size) |
|---|---|
| 본문 (한글) | 1.6–1.8 |
| 본문 (라틴) | 1.5–1.6 |
| 제목 (큰 글자) | 1.1–1.3 |

**경고 임계값**: 본문 비율 **< 1.5**이면 좁음(한글 기준), `< 1.3`이면 명백히 너무 좁음.
단위 없는 숫자(`line-height: 1.6`)를 권장 — px 고정은 폰트 변경에 취약.

같은 비율이라도 **폰트마다 실제로 보이는 줄 간격이 다르다** — 폰트가 자체 상하 여백을 갖기 때문이며,
한글 폰트는 그 편차가 특히 크다. 이 변수를 없애려면 §13-2 `text-box-trim`을 참고한다.

## 5. 위계 / 타입 스케일 (type scale)

**본문 기준 크기(base size)**: 웹 본문은 **최소 16px** — 브라우저 기본값이자 모바일(iOS)
자동 줌을 피하는 하한. 한글 장문은 **16~18px** 권장 — 한글은 획 밀도가 높고 어센더·디센더
여백이 없어 같은 px에서 라틴보다 작고 빽빽해 보인다. 어떤 뷰포트에서도 본문을 16px 아래로
내리지 않는다. (근거: 브라우저 기본 16px · Apple HIG 본문 17pt · Material 16sp)

모듈러 스케일로 본문 → 제목 크기를 단계적으로. 흔한 비율:

| 비율 | 이름 | body=16px 기준 스케일 |
|---|---|---|
| 1.25 | Major Third | 16 / 20 / 25 / 31 / 39 |
| 1.333 | Perfect Fourth | 16 / 21 / 28 / 38 / 50 |

h1 > h2 > h3 > body가 같은 비율로 이어지면 위계가 명확하고 일관된다.
인접 단계 크기 차이가 비율에서 ±15% 이상 벗어나면 `type-scale` 이슈로 본다.

**구조 역할(structural role)**: 문서를 이루는 덩어리를 역할로 나누고, 역할마다 크기·웨이트·명도·들여쓰기를
다르게 조판한다. **부제와 소제목은 다른 역할**이다 — 위치가 같아 보여도 조판 방향이 반대다.

| 역할 | 판별 | 조판 방향 |
|---|---|---|
| 제목(title) | 문서 첫 줄(≈80자 이하 — 제목은 짧은 명사구), 또는 `#` 마커. 긴 첫 줄은 본문 | 최대 크기·최진 명도 (§9) |
| 부제(subtitle) | 제목 **바로 아래** 짧은 딸림 줄, 또는 제목과 바이라인 **사이의 한 줄**(표제부 관례: 제목–부제–바이라인) | 본문보다 **옅게** — 제목의 보조 |
| 소제목(heading) | **본문 중간**의 짧은 줄(≈60자 이하)로 종결어미·종결부호 없이 끝남, 또는 `##` 마커 | 본문보다 **크고 굵고 진하게** + 위쪽 섹션 여백 — 새 섹션의 시작 신호 |
| 목록(list) | 번호(`1.`·`1)`)·기호(`-`·`•`) 마커로 시작하는 연속 줄 | 아래 목록 조판 |
| 참고 목록(ref) | "참고 자료/참고문헌/References" 소제목 **뒤에 이어지는 줄들** (다음 소제목 전까지) | 본문보다 **작게**(각주 관례)·보조 명도·행잉 인덴트 — 부속 정보로 분리 |
| 인용(quote) | `>` 마커, 또는 따옴표(`“`)로 시작하는 발췌 단락 | 세리프·들여쓰기·좌측 라인 (§9) |
| 캡션/메타(caption) | 날짜로 시작하는 바이라인, `작성자:` 류 라벨 | 최소 크기·최옅 명도 |

소제목 형태 판별의 근거: 한국어 산문 문장은 종결어미(-다/-요/-습니다)나 종결부호로 끝나므로,
그것 없이 끝나는 짧은 독립 줄은 표제(heading)일 확률이 높다 — 편집에서 표제는 명사(구)로 끝맺는 관례.

**목록 조판**: 번호·기호 목록은 본문과 다르게:
- 행간을 본문보다 **좁게**(예: 1.5).
- 항목 사이 여백은 **본문 단락 간격보다 좁게**(약 0.5–0.7em) — 항목끼리는 구분되고
  목록 전체는 한 묶음으로 읽힌다. 문단 길이의 긴 항목일수록 이 항목 간 여백이 필수다.
- 마커를 왼쪽으로 내어 둘째 줄이 글머리에 맞도록 **행잉 인덴트**.
- 마커 정규화: `1.:`처럼 마침표·콜론이 겹친 어색한 조합은 `1.`로(§7 결정적).

## 6. 자간 (letter-spacing)

- **큰 한글 제목** (≥ 28px): 약한 음수 트래킹 `-0.01em ~ -0.02em` — 큰 글자는 자간이 벌어 보임.
- **본문**: `letter-spacing: 0` (한글 본문에 양수 자간은 가독성 저해).
- **대문자 라틴 / 작은 라벨**: 약한 양수 `+0.02em ~ +0.05em` 허용.

## 7. 문장부호 / 공백 정리 (hygiene)

결정적으로 정규화 가능 (prose 영역에서만, `hygiene.mjs`가 멱등 적용):
- **이중 이상 공백** → 단일 공백.
- **부호 앞 공백 제거**: `텍스트 .` `텍스트 ,` `텍스트 !` → 붙임. (단, 여는 괄호·따옴표 앞 공백은 유지.)
- **부호 뒤 띄어쓰기 보완**: `다.특히` → `다. 특히` (마침표·쉼표·물음표·느낌표 뒤 다음 글자가 한글일 때만 — 영문 약어 `U.S.` 오탐 방지).
- **따옴표 일관화**: 한글 본문은 곧은 따옴표 `"` `'` 대신 둥근 따옴표 `“” ‘’` 권장(스타일 설정에 따름).
- **대시**: 범위는 엔대시 `–`, 삽입구는 엠대시 `—` 또는 양옆 공백 엔대시. 하이픈 `-` 오용 정리.
- **말줄임표**: `...` → `…` (한글 조판 관례). 말줄임표는 앞말에 붙여 쓰고 **뒷말과는 띄운다**
  (국립국어원) — `있었습니다...몇일` → `있었습니다… 며칠`.
- **영문 문장 첫 글자 대문자**: 줄(블록)이 소문자 영문 단어로 시작하면 첫 글자를 대문자로 (`this is a test` → `This is a test`). **오탐 방지**: 줄 맨 앞이 영문 소문자 + 뒤에 `공백+단어`가 이어지는 일반 문장만. 소문자로 시작하는 고유명사·식별자(`iPhone`, `npm`, `ceal-terview`)나 코드/URL(protected)·인라인코드는 제외. 형태로 확정되지 않는 경우(브랜드명 등 의심)는 §8(LLM 판단)으로 넘긴다.
- **기계적으로 안전한 띄어쓰기** (문맥 의존이 아니라 형태로 확정되는 것): 날짜+말 `2026-04-22하동훈`→`2026-04-22 하동훈`. — 일반 띄어쓰기는 §8.
- **괄호는 교정하지 않는다** (국립국어원 문장부호 규정): 여는 괄호는 **앞말에 붙여 쓴다** — `서울(Seoul)`, `하동훈(SE)`가 바른 표기이므로 띄우면 안 된다. 닫는 괄호 뒤는 조사면 붙이고(`(SE)이`) 새 어절이면 띄우는 문맥 판단이라 §8(LLM) 몫이다.
- 줄 끝 트레일링 공백 제거.

## 8. 맞춤법 / 띄어쓰기 / 오타 (LLM 판단)

기준 출처: **한글 맞춤법**(문화체육관광부 고시)·**국립국어원** 표준. 외부 API 없이 에이전트(LLM)가 본문을 읽고 이 기준으로 교정안을 제시한다.

**왜 LLM인가 (정규식의 한계)**: 한글 띄어쓰기는 문맥 의존이라 형태만으로 정규식 일괄 처리하면 오탐난다.
- 의존명사는 띄움(`할 것`, `먹을 수`, `갈 데`)이지만, 같은 글자가 붙는 경우(`이것`·`그것`, `만큼`이 조사일 때)와 구분 못 함.
- 보조용언(`해 보다`/`해보다`), 합성어(`큰집` vs `큰 집`)는 의미로 갈린다.
- **닫는 괄호 뒤**: 조사는 붙이고(`하동훈(SE)이 말했다`) 새 어절은 띄운다(`(SE) 직함처럼`) — 형태로 구분 불가, 문맥으로만 판단.
- 따라서 **형태로 확정되는 안전한 띄어쓰기만 §7 스크립트**가 처리하고, 나머지는 LLM이 문맥으로 판단한다.

교정 범위:
- 명백한 오타·맞춤법·문맥 의존 띄어쓰기.
- **사실 정합성 의심**: 미래 날짜(작성 시점보다 뒤), 숫자 불일치 등은 *교정이 아니라 질문*으로 표시.
- 문체는 함부로 바꾸지 않는다 — 오류 교정에 한정, 리라이팅은 사용자 요청 시에만.

**흔한 오타 사전(단일 기준)** — 형태가 확정적이라 LLM이 우선 적용한다. studio도 동일 사전을 쓴다:
| 틀림 | 맞음 | 틀림 | 맞음 |
|---|---|---|---|
| 되요 | 돼요 | 됬 | 됐 |
| 역활 | 역할 | 바램 | 바람 |
| 몇일 | 며칠 | 왠만 | 웬만 |
| 오랫만 | 오랜만 | 금새 | 금세 |
| 웬지 | 왠지 | 구지 | 굳이 |
| 어떻해 | 어떡해 | | |

**의존명사 '수' 띄어쓰기** — `할수있다`→`할 수 있다`. 어간 받침(`할·볼·줄·들·올·갈·날·살·말·될·쓸·길·물·풀·틀·벌`) + `수` + `있/없`가 붙어 있으면 의존명사이므로 양쪽을 띄운다. 형태로 거의 확정되지만 문맥 예외(고유명사 '수' 등)가 있을 수 있어 §8(LLM 판단)에 둔다.

## 9. 위계 강화 — 명도 대비 · 웨이트 · 폰트 페어링

크기(§5)만으로는 위계가 약하다. 세 축을 함께 써야 위계가 또렷해진다.

**명도(value) 대비** — 흰 종이 위에서 진함→옅음 램프로 읽는 순서를 만든다:
| 역할 | 명도(예시) | 비고 |
|---|---|---|
| 제목 | `#14161b` | 가장 진함 — 시선이 먼저 닿음 |
| 소제목(섹션, §5) | `#14161b`~`#1c2027` | 제목과 같은 급으로 진하게 — 새 섹션의 시작 신호 |
| 본문 | `#2b2f37` | 순흑(`#000`) 금지 — 눈부심·피로 |
| 부제(§5) | `#5f6675` | 본문보다 한 단계 옅게 — 제목의 보조 |
| 참고 목록(§5) | `#5f6675` | 부속 정보 — 본문과 분리 |
| 캡션/메타 | `#9aa1ad` | 가장 옅음 — 흐름 방해 안 함 |
본문은 **순흑을 쓰지 않는다**(진회색). 명도 단계가 역전되면(캡션이 본문보다 진함) 위계 오류.
**소제목(heading)과 부제(subtitle)는 명도 방향이 반대**다: 소제목은 진하게(구획 신호), 부제는 옅게(보조).

**웨이트(weight)**: 제목 700–800, 소제목 700, 부제 600, 본문 400. 본문에 볼드 남발 금지(강조는 국소).

**폰트 — 단일 폰트가 기본**: 위계는 **크기와 웨이트만으로 충분히** 만들 수 있다(명도는 보조).
제목이 본문과 다른 폰트일 필요는 없다 — 산세리프 1종으로 통일하는 것이 기본값이다.
폰트 페어링(본문 산세리프 + 제목/인용 세리프)은 질감 대비가 필요할 때만 쓰는 **선택 강화 수단**이며,
쓰더라도 한 문서에 **2종**을 넘기지 않는다.

## 10. 단락 리듬 (세로 운율 / vertical rhythm)

문단 사이 여백을 본문 글자 크기에 비례해(약 `0.8–1.4em`) 일정하게 두면 세로 리듬이 생겨
문단 덩어리가 분명해지고 스캔이 쉬워진다. 줄간(§4)과 단락간 간격의 **대비**가 핵심 —
단락 간격이 줄간보다 충분히 커야 문단 경계가 읽힌다.

**표제부와 본문의 분리**: 표제부(제목·부제·바이라인)가 끝나고 본문이 시작되는 지점은
일반 단락 간격보다 **큰 섹션급 여백**으로 띄운다 — 문서의 "머리"와 "몸"이 구분되어야
독자가 본문 시작을 명확히 인지한다. 표제부 내부(부제↔바이라인)는 반대로 좁혀 한 덩어리로 묶는다.

## 11. 레이아웃 — 시각 요소(이미지) 자리 제안

긴 본문이 끊김 없이 이어지면 시선이 지친다. 의미가 전환되는 지점(섹션 사이, 본문 중반)에
**이미지/도식이 들어갈 자리**를 제안해 호흡과 스캔 포인트를 만든다.

**개수 — 본문 분량에 비례**: 장문 아티클은 화면 2–3 스크린마다 시각 휴지를 두는 것이 웹 편집 관행.
본문 기준으로 환산하면 **약 1,000자(공백 포함, 문단 3–4개 분량)당 1곳**, 문서당 **최대 4곳**.
본문 블록이 2개 미만이면 제안하지 않는다.

**위치 — 우선순위**:
1. **섹션 전환점**(소제목 바로 앞) — 의미가 끊기는 자리라 흐름을 해치지 않는다.
2. 소제목이 없으면 **긴 본문 연속 구간의 중간** 문단 앞.
3. 배분은 전체 분량을 (개수+1) 등분한 지점에 가장 가까운 후보를 고른다 — 몰리지 않고 고르게.

- 16:9 등 비율 영역을 **플레이스홀더로 표시**.
- 실제 이미지는 사람이 채운다 — 도구는 *위치·비율 제안*까지만(자동 삽입 금지).

## 12. AI 글 흔적 보정 (AI writing tells)

LLM이 쓴 글에는 사람 글과 다른 미묘한 형태 습관이 있다. 여기서는 **형태로 확정되는 기호 패턴만**
교정한다 — 상투어·문장 구조·문체는 형태로 확정되지 않으므로 §8(LLM 판단)에서 *제안*만 하고
강제하지 않는다(스킬 원칙: 문체는 함부로 바꾸지 않는다).

**결정적 교정 (형태 확정, §7과 함께 hygiene에서)**:
- **양옆 공백 엠대시 삽입구** `A — B — C`, `A — B`: 영문 조판 습관으로, 한국어 본문에선 어색하다.
  삽입구는 쉼표(`A, B, C`)나 괄호로, 문장 연결이면 문장을 나눈다. — 대시 자체가 정당한 용법
  (범위 엔대시 `1–10`, 앞뒤 공백 없는 하이픈)은 건드리지 않는다.
- **화살표를 산문에 사용** `A -> B`, `A => B`(코드가 아닌 prose): 한국어 산문에선 `→` 또는
  말로 풀어 쓴다. protected(코드·인라인코드) 안은 제외.
- **제목·목록 앞 이모지** `## 🚀 시작하기`, `- ✅ 완료`: 편집 문서에선 제거. 본문 중간의
  의미 있는 이모지는 유지(형태로 구분: 줄/항목 맨 앞의 단독 이모지만).
- **과한 병렬 볼드** 한 문장·항목 안에 `**...**`가 3개 이상이면 강조 남발로 본다 → 개수를 줄이도록
  *제안*(자동 제거는 안 함 — 어느 것을 남길지는 문맥 판단).

**판단 제안만 (§8, 강제 안 함)**: 상투어(`~에 있어`, `결론적으로`, `중요한 점은`, `뿐만 아니라`),
공허한 강조 필러(`이는 매우 중요합니다`), 뭐든 3항목으로 나누는 습관 등은 *간결화 제안*으로만
남긴다. 문체 교정은 사용자가 요청할 때만.

## 13. 최신 CSS Text 기능 (2026-08 Baseline 기준)

지금까지의 줄바꿈 교정(§1 glue·§2 마지막 줄 한 단어)은 **스크립트가 `&nbsp;`를 삽입해 한 폭에서
흉내내는 방식**이다. 최신 CSS Text/Typography 속성은 **브라우저가 모든 폭에서** 같은 일을 하게
하므로, 지원되면 CSS에 1차로 위임하고 nbsp 삽입은 **미지원·잔여 폴백**으로 내린다.

**역할 재정의 (핵심)**: CSS(전 폭 대응)가 1차, nbsp 삽입(§1·§2, 스크립트·런타임)은 폴백.
지원 브라우저에서는 CSS가 처리하므로 **같은 지점에 nbsp를 중복 적용하지 않는다**(아래 중복 회피).

### 13-1. 지금 채택 — Baseline Newly Available (2024-10~)

| 속성 | 값 | 대상 | 대체/보완하는 규칙 |
|---|---|---|---|
| `text-wrap` | `pretty` | 본문(p·li) | §2 마지막 줄 한 단어 — 고아를 브라우저가 자동 축소 |
| `text-wrap` | `balance` | 제목·부제(h1~h3, ≤6줄) | 제목 줄 길이 균등 — 위계(§5·§6) 강화 |

```css
/* 본문 */
p, li { text-wrap: pretty; }
/* 제목 — 짧은 다줄 제목의 균형 (6줄 이하에서만 동작) */
h1, h2, h3 { text-wrap: balance; }
```

- **효과**: `pretty`는 단락 마지막 줄에 한 단어만 남는 것을 브라우저가 줄인다 → §2 교정의 1차를
  CSS로 위임. `balance`는 여러 줄 제목의 줄 길이를 고르게 맞춘다.
- **폴백**: Firefox는 `pretty` 미지원(2026 기준) → 미지원 시 기본 줄바꿈으로 **깨짐 없이 폴백**한다.
  따라서 `pretty`는 진보적 향상(progressive enhancement)이고, **Firefox·CJK 잔여분은 런타임
  스크립트(§2 nbsp)가 폴백으로 처리**한다 — 이 이중 구조가 정당한 이유다.
- **중복 회피**: 본문에 `text-wrap: pretty`가 적용돼 있으면(그리고 대상이 그 CSS를 실제로 받는
  브라우저면) §2 orphan nbsp 제안을 **보류**한다 — 둘 다 걸면 좁은 폭에서 과교정된다. 확신이
  없으면(정적 폴백·구형 지원 불명) nbsp를 유지해 안전을 택한다.

### 13-2. 진보적 향상 — 아직 비-Baseline (2026-08, `@supports`로 감쌀 것)

지원이 넓지 않으므로 **필수 의존 금지**. 반드시 `@supports`로 감싸 제안하고, 미지원 폴백은
현행(§1·§4·§7) 그대로 둔다.

| 속성 | 효과 | 2026-08 지원 | 반영 규칙 |
|---|---|---|---|
| `text-spacing-trim: trim-start`(또는 `normal`) | CJK 전각 구두점(`。「」（）`) 내부 여백 자동 커닝 | Chromium 선행, 비-Baseline | §7 문장부호 — CSS 제안 |
| `text-autospace: normal` | CJK↔라틴/숫자 사이 간격 자동 삽입 | 실험적, 비-Baseline | §1 혼합 문서 — **§1 glue와 조율 필요** |
| `text-box-trim` **+ `text-box-edge`(필수 동반)** | 폰트가 넣는 상하 여백을 잘라 **폰트별 편차를 제거** → §4 행간·§10 여백의 지정값이 그대로 보이게 한다. trim 값: `trim-start`·`trim-end`·`trim-both`·`none`. **적용 대상: 블록 컨테이너·인라인 박스 / 상속: 안 됨** | Limited(비-Baseline) | §4 행간·§10 단락 리듬의 전제 조건, §6 위계 — 제목/본문 광학 정렬 |
| `hanging-punctuation: first last` | 첫/끝 구두점을 글줄 밖으로 걸어 광학 정렬 | **Safari 한정**(호환성 낮음) | §7 — "Safari 한정" 명시, 강제 안 함 |

```css
@supports (text-spacing-trim: trim-start) {
  :root { text-spacing-trim: trim-start; }   /* CJK 구두점 커닝 */
}
/* 단축(text-box)을 쓰면 게이트도 단축으로 물어야 한다 — @supports는 문자열 파싱이라
   longhand만 아는 엔진에서 게이트를 통과한 뒤 선언이 통째로 무시된다. */
/* text-box-trim은 상속되지 않는다 — text-spacing-trim처럼 :root에 걸면 자식에게 전파되지 않아
   아무 효과가 없다. 반드시 대상 요소(또는 그 요소를 포함하는 셀렉터)에 직접 건다. */
@supports (text-box: trim-both cap alphabetic) {
  h1, h2, h3 { text-box: trim-both cap alphabetic; }   /* 제목 상하 여백 정리 */
  p, li      { text-box: trim-both cap alphabetic; }   /* 본문도 필요하면 직접 지정 */
}
```

- **`text-autospace` ↔ §1 glue 조율**: 둘 다 CJK↔숫자 경계를 다룬다. `text-autospace`는 *간격을
  넣고*, §1 glue는 *줄바꿈을 막는다* — 목적이 달라 공존 가능하지만, 혼합 문서에서 자동 간격을
  켤 때는 §1이 넣은 nbsp가 이중 간격을 만들지 않는지 확인한다(자동 간격 채택 시 순수 공백 유지).
- **`text-box-trim`은 단독으로 무효**: trim은 *어느 모서리*를, `text-box-edge`가 *얼마나*를 정한다 —
  edge 없이 trim만 걸면 지원 브라우저에서도 아무 일도 일어나지 않는다(미지원 폴백과는 성격이 다른
  실패다). 반드시 `text-box` 단축이나 두 속성을 함께 제안한다.
- **한글에서 특히 중요한 이유(§4·§5 연결)**: 폰트마다 자체 상하 여백이 달라 같은 `font-size`·
  `line-height`라도 line box 높이가 달라진다. 한글 폰트는 이 편차가 라틴보다 크고(§5 — 어센더·
  디센더 여백 관행이 제각각), 그래서 §4의 1.6–1.8 권장값이 폰트에 따라 다르게 **보인다**.
  `text-box-trim`은 그 변수를 없애 §4·§10의 숫자를 신뢰할 수 있게 만드는 **전제 조건**이지,
  이미 맞는 리듬에 얹는 장식이 아니다.
- **`hanging-punctuation`**: Safari에서만 의미 있는 효과. 제안은 하되 "Safari 한정, 미지원 시 무효
  (레이아웃 안 깨짐)"를 근거에 적고 자동 적용하지 않는다.

### 13-3. Baseline 게이트 원칙

- **Newly Available 이상**(13-1)은 폴백만 확인하고 채택한다.
- **비-Baseline**(13-2)은 반드시 `@supports (속성: 값)`로 감싸 제안하고, 미지원 경로의 동작(현행
  유지)을 diff 근거에 함께 적는다.
- 모든 CSS 신기능은 `css-rule` 카테고리로, **자동 삽입하지 않고** 대상 파일·셀렉터를 제안해 사람이
  승인·배치한다(§7 hygiene의 결정적 텍스트 교정과 구분).
